# Общий сервер команды

Основной общий сервис команды запускается в GitHub Codespaces (порядок — в [../README.md](../README.md), раздел «Где работает»). Тот же состав контейнеров подходит для собственной виртуальной машины с постоянным диском.

Одна копия приложения обслуживает команду и преподавателей по личным логинам. Заявки, решения и журнал хранятся в SQLite вместе с автором действия. Стенд продолжает обслуживать очередь при отказе модели. На пользовательских компьютерах нужен браузер.

## Состав

| Сервис | Роль | Хранение |
|---|---|---|
| proxy | Caddy принимает HTTPS и передаёт запросы веб-приложению | Сертификаты в постоянном томе |
| app | Рабочее место, авторизация, принятие, изменение и отклонение, аудит | Том state с team.sqlite |
| tools | MCP-чтение текущей заявки и статей. Процесс без сети и паролей взаимодействует через Unix-сокет | База из тома state только на чтение, статьи — в образе |
| ollama | Одна Qwen 2.5 0.5B для всех инженеров; API слушает loopback в сетевом пространстве приложения | Том weights с весами |

## Развёртывание на Linux VM

Понадобятся постоянно работающая VM с Docker Engine и Compose, DNS-имя, направленное на VM, и входящие TCP 80 и 443 для Caddy. Команды выполняются в папке stage2 на сервере. Одновременно запускается один экземпляр app с его постоянным томом. Код первого этапа и GitHub Pages могут работать независимо.

1. Введите собственное публичное имя стенда в STP_DOMAIN. Для следующего запуска сохраните это значение в файле .env на сервере.
2. Создайте личные учётные записи команды и преподавателей. Генератор сохраняет их в закрытом каталоге team-access/users.json и при повторном запуске сохраняет существующие пароли. Дайте группе контейнера доступ к файлу для чтения.
3. Запустите сервисы и загрузите модель один раз.

```sh
export STP_DOMAIN=stp.example.org
python3 server/make_users.py
sudo chgrp 10001 team-access/users.json
chmod 640 team-access/users.json
docker compose config -q
docker compose up -d --build
docker compose exec ollama ollama pull qwen2.5:0.5b
```

Проверьте HTTPS по имени из STP_DOMAIN. Сервис покажет страницу входа. Передайте каждому участнику только его логин и пароль отдельным каналом. Для диагностики используйте `docker compose ps` и `docker compose logs --tail 80`. Том state содержит решения команды и журнал, поэтому его следует сохранять при обновлениях. Команда `docker compose down -v` удаляет данные.

## Приёмка

Влад открывает ES-9101 и запрашивает черновик; Мария видит тот же черновик под своим логином и принимает его. Елизавета обновляет карточку и проверяет текст ответа и автора действия в журнале. После перезапуска app обе записи доступны в той же заявке. В новой учебной сессии для повторения используйте другую открытую заявку.

Автоматический эквивалент сценария, включая повторное решение и перезапуск приложения, выполняется из корня проекта при доступной локальной Ollama с моделью:

```sh
python3 stage2/server/verify_shared.py
```

Проверка создаёт свои временные учётные записи и базу. Статический режим GitHub Pages хранит ответы в текущей вкладке. Для совместной работы участникам передают адрес серверного стенда.

## Вариант с бесплатной квотой GitHub Codespaces

Для совместного показа достаточно одного Codespace в личном аккаунте. Все участники открывают один порт одного экземпляра. Владелец запускает Codespace перед демонстрацией и останавливает его после работы. Если рабочее пространство остановлено, посещение публичного порта само по себе его не запускает.

У личного GitHub Free включены 120 ядро-часов и 15 ГБ-месяц хранения. Для машины с двумя ядрами это до 60 часов работы в месяц при полностью свободной квоте. Чтобы исключить расходы, используйте аккаунт без способа оплаты либо проверьте жёсткий нулевой бюджет Codespaces с остановкой использования. Хранение учитывается и в остановленном состоянии. Удаление Codespace удаляет его локальное состояние; сохраните резервную копию базы перед удалением. [Правила расчёта](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces).

Настройки рабочего пространства лежат в `.devcontainer/devcontainer.json` (образ с Docker, 2 ядра и 8 ГБ памяти, порт 8765). Из корня репозитория запустите:

```sh
bash stage2/server/start_codespace.sh
```

Скрипт создаёт личные учётные записи, собирает приложение и сервер инструментов, скачивает модель и пытается сделать порт 8765 публичным. Если это не удалось, на панели Ports сделайте публичным только порт 8765. GitHub предоставляет HTTPS, приложение запрашивает персональные данные для входа. Веса модели и сервис инструментов не публикуют порты. Файл очереди находится в stage2/team-access/state/team.sqlite внутри постоянного рабочего каталога. Файл входа stage2/team-access/users.json исключён из Git. После остановки и повторного запуска используйте тот же Codespace.
