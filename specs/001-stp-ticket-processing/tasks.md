# Tasks: Обработка обращений в службу технической поддержки (СТП)

**Input**: Design documents from `/specs/001-stp-ticket-processing/`

**Prerequisites**: plan.md, spec.md, research.md, quickstart.md

**Tests**: включены. Их требуют принцип конституции P7 (критерии приёмки → автотесты), решение R12 плана и требование ИИ-07 (набор ≥ 20 сценариев prompt injection). Тесты истории пишутся первыми и должны не проходить до реализации.

**Organization**: задачи сгруппированы по пользовательским историям US1–US6 из spec.md; каждую историю можно реализовать и проверить отдельно.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно выполнять параллельно (другой компонент или независимая часть, нет зависимостей от незавершённых задач)
- **[Story]**: история из spec.md (US1…US6)
- Вместо путей к файлам указан компонент из plan.md и `docs/05-traceability.md` (C-PORTAL, C-DESK, C-TICKET, C-SLA, C-NOTIFY, C-BUS, C-REF, C-REPORT, C-AUDIT, C-AGENT, MCP-*). Структура кода и файлы определяются на этапе 2 после выбора технологий.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: без зависимостей
- **Foundational (Phase 2)**: после Setup — блокирует все истории
- **User Stories (Phase 3–8)**: после Foundational; по приоритету P1 → P6 или параллельно
- **Polish (Phase 9)**: после нужных историй

### User Story Dependencies

- **US1 (P1)**: только Foundational
- **US2 (P2)**: только Foundational; T036 дополняет регистрацию из US1 (T024) — при раздельной разработке выполняется после T024
- **US3 (P3)**: только Foundational; использует тестовые заявки
- **US4 (P4)**: использует календарь из US2 (T034) для правила 3 рабочих дней
- **US5 (P5)**: только Foundational; тестовый набор за октябрь
- **US6 (P6)**: событие «заявка зарегистрирована» из US1; применение решения — через смену исполнителя из US3 (T046)

### Within Each User Story

- Тесты пишутся первыми и не проходят до реализации
- Данные → логика компонента → операции → интерфейс
- История завершена до перехода к следующему приоритету

### Parallel Opportunities

- Setup: T003, T004
- Foundational: T006, T010, T011, T013, T016, T018
- Тесты каждой истории, отмеченные [P], — параллельно
- US6: серверы инструментов T072–T074, маскирование T075 и подключение модели T076 — параллельно

## Implementation Strategy

### MVP First (User Story 1 + 2)

1. Phase 1 и Phase 2
2. US1 — регистрация и уведомления; **STOP and VALIDATE** (Q1, Q2, Q11)
3. US2 — контроль SLA; **STOP and VALIDATE** (Q3–Q7). US1 + US2 — минимальный продукт, ради которого существует система: заявки не теряются и SLA контролируется

### Incremental Delivery

1. US3 → US4 → US5 — полный процесс кейса и отчёты
2. US6 — ИИ-ассистент поверх готового ядра; отключение не ломает US1–US5

## Notes

- [P] — другой компонент или независимая часть, нет зависимостей
- Метка [USn] связывает задачу с историей для трассируемости
- Коммит после каждой задачи или логической группы
- На любой контрольной точке историю можно проверить отдельно
