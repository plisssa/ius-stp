# Quickstart: проверка сценариев от начала до конца

**Feature**: [spec.md](./spec.md) · **Plan**: [plan.md](./plan.md)

Руководство для проверки готовой реализации. Команды и пути соответствуют структуре из `plan.md`; данные и контракты — в [data-model.md](./data-model.md) и [contracts/](./contracts/).

## Подготовка

1. Нужны Docker и Docker Compose (приложение, worker, PostgreSQL, Mailpit, заглушка Slack, ассистент, MCP-серверы).
2. Запуск окружения: `docker compose up -d`.
3. Миграции и тестовые данные: `docker compose run --rm app python -m stp.seed`. Создаются:
   - организация «Альфа» — стандартная поддержка, SLA в **рабочих** часах, P1–P4 = 1 / 4 / 8 / 24 ч;
   - организация «Бета» — расширенная поддержка, SLA в **календарных** часах, те же нормативы;
   - клиенты Иванов и Петрова («Альфа»), Сидоров («Бета»);
   - инженеры L1 (2), L2 (1), L3 (1) и руководитель;
   - производственный календарь РФ на 2026–2027 годы.
4. Управляемые часы для проверки временных правил: `STP_CLOCK=fixed:2026-11-09T10:00:00+03:00`; сдвиг — `docker compose run --rm app python -m stp.clock advance 3h`.
5. Почта: веб-интерфейс Mailpit на `http://localhost:8025`; сообщения Slack — в журнале сервиса `slack-stub`.

|---|---|---|---|---|

| Q2 | Видимость своей организации | Сидоров («Бета») открывает `ES-0001` по прямой ссылке | Ответ 403 | FR-004 |

| Q4 | Дедлайн в календарных часах | Часы — суббота 10:00, Сидоров создаёт заявку P2 | Дедлайн — суббота 14:00 | FR-007 |
| Q5 | Предупреждение и нарушение SLA | Заявка из Q4, сдвинуть часы до 13:00, затем до 14:00 | В 13:00 — одно письмо каждому инженеру; в 14:00 — отметка «SLA нарушен», письма всем инженерам и руководителю | FR-008, FR-009 |

## Автоматическая проверка

`docker compose run --rm app pytest` — модульные, контрактные и интеграционные тесты; сценарии Q3–Q11 выполняются с подменой часов, Q16 — на наборе вредных заявок.
