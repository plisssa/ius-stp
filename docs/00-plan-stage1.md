## Spec Kit: команды

```bash
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git
```

```bash
specify init . --ai claude
```

Флаг выбора агента в разных версиях называется по-разному (`--ai` или `--integration`), поэтому сначала проверьте `specify init --help`. Дальше в Claude Code — слэш-команды `/speckit.constitution`, `/speckit.specify`, `/speckit.plan`, `/speckit.tasks`. Конституция Spec Kit хранится в `.specify/memory/constitution.md`.

**Что подать в `/speckit.specify`** (только «что» и «зачем», без технологий):

> Система обработки обращений в службу технической поддержки (кейс 12). Клиенты — сотрудники организаций, эксплуатирующих ПО, — создают заявки через веб-портал. Заявка получает идентификатор ES-NNNN, статус Waiting for support и исполнителя Unassigned. Система контролирует SLA первого ответа (дедлайн по приоритету, предупреждение за 1 час, письмо о нарушении) и рассылает уведомления на почту и в Slack. Она поддерживает назначение и эскалацию, статус Waiting for customer, закрытие (в том числе при отсутствии ответа клиента 3 рабочих дня), возобновление в течение 2 недель и три отчёта. ИИ-ассистент только предлагает инженеру тип обращения, оценку приоритета, исполнителя и черновик ответа; все решения утверждает человек. Правила и требования — в docs/01–04 (BR, EARS, ИИ). Не добавлять правил, которых нет в кейсе; неясности отмечать как [NEEDS CLARIFICATION] со ссылкой на ASM.

**Что подать в `/speckit.plan`** (решение принимаете вы на G4; это предложение):

> Python 3.12 и FastAPI; PostgreSQL; веб-интерфейс на React или серверные шаблоны. Таймеры SLA — планировщик, работающий от сохранённого дедлайна. Почта и Slack на прототипе — заглушки. ИИ-ассистент — агент в harness с доступом только через MCP-серверы-заглушки (tickets, kb, staff). Фрагмент для прототипа с агентом на этапе 2 — триаж новой заявки (EARS-14, EARS-15).
