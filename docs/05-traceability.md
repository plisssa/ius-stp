# 5. Матрица трассируемости

Матрица показывает, как каждое ключевое требование связано с правилом кейса, элементом модели процесса, будущим элементом архитектуры и задачами.

Полная цепочка: **требование (EARS) → правило кейса (BR) → элемент модели процесса (BPMN) → компонент архитектуры → требование спецификации (FR) → задачи**.

## 5.1. Будущие элементы архитектуры

Компоненты выделены по ответственности, в стиле C4 (уровень контейнеров, лекция 3). Как они будут развёрнуты и на каких технологиях — решается на этапе 2; модули кода добавляются в матрицу после реализации (задача T085).

| ID | Компонент | Ответственность |
|---|---|---|
| C-PORTAL | Портал клиента (веб) | Создание заявок, переписка, обратная связь, возобновление |
| C-DESK | Рабочее место инженера и руководителя (веб) | Очередь, карточка заявки, назначение, эскалация, экран утверждения предложений ассистента |
| C-TICKET | Сервис заявок | Номера, статусы, исполнитель, переписка, правила закрытия и возобновления |
| C-SLA | Контроль сроков | Сроки первого ответа, проверка по расписанию, производственный календарь |
| C-NOTIFY | Уведомления | Письма и сообщения в Slack по событиям |
| C-BUS | Передача событий | Доставка событий между компонентами с гарантией доставки (R7) |
| C-REF | Справочники | Организации и нормативы SLA, инженеры (уровень, компетенции), типы, приоритеты, инсталляции |
| C-REPORT | Отчёты | Отчёты ФТ-27…29, расчёт KPI |
| C-AUDIT | Журнал аудита | Неизменяемая история изменений и решений |
| C-AGENT | ИИ-ассистент | Предложения А1–А4, ограничения, журнал вызовов инструментов |
| MCP-TICKETS, MCP-KB, MCP-STAFF | Серверы инструментов ассистента | Доступ ассистента к заявкам, базе знаний, данным об инженерах (разрешённый список — `docs/04` §4.1 и `plan.md`) |
