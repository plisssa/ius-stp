Каждое требование ссылается на бизнес-правило (BR) или допущение (ASM) из `01-process-analysis.md` и на элемент модели процесса (идентификаторы вида T_…, GW_…, ICE_… — см. раздел 1.5 там же).

## 2.2. KPI процесса

Базовые значения AS-IS в кейсе не приведены. Их нужно измерить после запуска или взять из отчётов СТП. Целевые значения — предложение для согласования.

| ID | Показатель | Формула | Разрез | Цель (предл.) |
|---|---|---|---|---|
| KPI-01 | Соблюдение SLA первого ответа | заявки с первым ответом до дедлайна / все заявки с наступившим дедлайном × 100 % | приоритет, организация | ≥ 95 % |
| KPI-02 | Время первого ответа | медиана и 90-й перцентиль (первый ответ − регистрация) | приоритет | ≤ 50 % норматива (медиана) |
| KPI-03 | Время назначения исполнителя | медиана (назначение − регистрация) | приоритет | снижение на 30 % к базе |
| KPI-04 | Время решения | медиана (закрытие «решено» − регистрация) | тип, приоритет | измеряется, без цели (SLA на решение в кейсе нет) |
| KPI-05 | Доля эскалаций | эскалированные / все × 100 % | тип, продукт | контроль тренда |
| KPI-06 | Доля возобновлённых заявок | возобновлённые в течение 2 недель / закрытые «решено» × 100 % | тип, инженер | ≤ 5 % |
| KPI-07 | Доля возвратов на повторную диагностику | заявки с «не помогло» / заявки с решением × 100 % | тип | ≤ 15 % |
| KPI-08 | Закрытие по отсутствию ответа | закрытые «нет ответа клиента» / все закрытые × 100 % | организация | контроль тренда |
| KPI-09 | Качество входных данных | заявки с исправленным приоритетом или инсталляцией / все × 100 % | организация | контроль тренда |
| KPI-10 | Загрузка инженеров | активные заявки на инженера (среднее, макс.) | инженер | разброс ≤ 2× |
| KPI-11 | Неудовлетворённые обращения | число сотрудников из отчёта ФТ-28 за период | организация | снижение к базе |

KPI ИИ-компонента (доля принятых предложений и другие) — в `04-ai-requirements.md`.

## 2.3. Нефункциональные требования (НФТ)

Структура — по характеристикам качества ISO/IEC 25010:2023. Класс критичности — по лекции 1.3.

| ID | Характеристика | Требование | Обоснование |
|---|---|---|---|
| НФТ-01 | Надёжность — класс критичности | Business operational: доступность портала и сервиса заявок ≥ 99,5 % в месяц; RTO ≤ 2 ч; RPO ≤ 1 ч | Внутренний сервис уровня CRM (лекция 1.3: RTO/RPO — часы). Заявки, потерянные за последний час, восстанавливаются из уведомлений на почту и в Slack, которые уходят по каждому событию (BR-12) |
| НФТ-02 | Надёжность — SLA-контур | Дедлайн вычисляется и сохраняется при регистрации; предупреждения и нарушения определяются от сохранённого дедлайна с погрешностью ≤ 1 мин, в том числе после перезапуска и восстановления | Таймер не может «потеряться» при сбое (BR-08…11) |
| НФТ-03 | Производительность | Регистрация заявки ≤ 2 с, открытие карточки ≤ 1,5 с (95-й перцентиль); отчёт за год ≤ 10 с | Работа инженера в реальном времени |
| НФТ-04 | Производительность — доставка | Уведомление отправлено ≤ 1 мин после события (95-й перцентиль) | BR-12, своевременность реакции |
| НФТ-05 | Производительность — нагрузка | Расчёт на 500 заявок в сутки и 100 одновременных пользователей с запасом ×3 (**допущение**, в кейсе объёмов нет) | Масштабирование без переделки |
| НФТ-06 | Защищённость — доступ | Ролевая модель: Клиент, Инженер, Руководитель, Администратор; клиент видит только заявки своей организации | Конфиденциальность данных клиентов |
| НФТ-07 | Защищённость — аутентификация | Клиенты — учётные записи портала; сотрудники — корпоративная аутентификация (SSO); сессии с тайм-аутом | — |
| НФТ-08 | Защищённость — аудит | История изменений неизменяема; хранится не меньше срока действия договора SLA (предл. 3 года) | Разбор споров по SLA |
| НФТ-09 | Защищённость — ПДн | ФИО и контакты клиентов — персональные данные (152-ФЗ): хранение в РФ, маскирование перед передачей во внешние сервисы, в том числе в языковую модель | Регуляторика |
| НФТ-10 | Совместимость | Интеграция с почтой (SMTP) и Slack (API); все интеграции — через документированные API; ИИ-агент — только через MCP-серверы | Принцип N×M → N+M |
| НФТ-11 | Взаимодействие с пользователем | Веб-интерфейс; оставшееся время SLA видно в очереди и карточке; статусы называются как в кейсе | Снижение ошибок инженеров |
| НФТ-12 | Сопровождаемость | Нормативы SLA, сроки (3 рабочих дня, 2 недели), шаблоны уведомлений и справочники настраиваются без изменения кода | Изменения договоров SLA |
| НФТ-13 | Сопровождаемость — наблюдаемость | Метрики, логи и трейсы сервисов; журнал вызовов инструментов агента; стоимость вызовов модели | Сквозное требование курса |
| НФТ-14 | Функциональная пригодность — календарь | Рабочие дни (правило 3 рабочих дней) и рабочие часы SLA — по производственному календарю РФ и часовому поясу организации-клиента; для договоров в календарных часах SLA считается круглосуточно | ASM-07 |
| НФТ-15 | Безопасность (safety) | ИИ-компонент не выполняет необратимых действий без человека; доступ агента к серверам клиентов запрещён | Красная линия курса, BR-17 |
