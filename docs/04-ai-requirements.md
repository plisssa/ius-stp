# 4. Требования к ИИ-компоненту

> Статус: **утверждено на human-gate G2 (07.11.2026)**.
> Целевые значения метрик — экспертные ориентиры для согласования. Обосновать их можно только на размеченной выборке заявок (см. ИИ-09).

## 4.1. Назначение и уровень полномочий

**Компонент:** ИИ-ассистент инженера СТП («триаж-ассистент»).

**Уровень полномочий** по лекции 3 — **2. «Агент-ассистент: черновик + human-gate»**. Ассистент готовит предложения, применяет их только человек.

| Функция | Что предлагает | Кто утверждает | Шаг процесса |
|---|---|---|---|
| А1 | Тип обращения | Инженер | T_AIProposal → T_Check |
| А2 | Оценку соответствия приоритета описанию (флаг + обоснование) | Инженер решает, запрашивать ли обоснование у клиента (BR-14) | T_Check |
| А3 | Рекомендуемого исполнителя | Инженер (взять) или руководитель (назначить) | GW_Free, T_HeadAssign |
| А4 | Черновик первого ответа или запроса диагностики | Инженер | T_Answer, T_RequestInfo |

**Чего ассистент делать не может** (жёсткий запрет, проверяется на уровне инструментов):
- отправлять что-либо клиенту;
- менять приоритет, тип, исполнителя, статус заявки;
- закрывать заявки;
- обращаться к серверам клиентов (удалённый доступ, BR-17);
- рассылать уведомления.

**Предварительный состав инструментов** (уточняется на этапе 2 как MCP-серверы):

| Инструмент | Доступ | Назначение |
|---|---|---|
| `tickets.get`, `tickets.search_similar` | только чтение | Текст заявки, похожие закрытые заявки |
| `kb.search` | только чтение | База знаний СТП, документация ПО |
| `staff.get_load`, `staff.get_competences` | только чтение | Загрузка, уровень и компетенции инженеров, история с клиентом |
| `proposal.save` | запись **только** в поле «предложение ассистента» | Сохранить предложение для показа инженеру |

## 4.2. Требования

### Качество (точность и доля ошибок)

| ID | Требование | Метрика и целевое значение | Как проверяется |
|---|---|---|---|
| ИИ-01 | А1: классификация типа обращения | Accuracy ≥ 85 %, macro-F1 ≥ 0,80 | Отложенная размеченная выборка ≥ 200 заявок |
| ИИ-02 | А2: выявление несоответствия приоритета | Полнота ≥ 70 % при точности ≥ 60 % | Выборка заявок, где инженер менял приоритет |
| ИИ-03 | А3: рекомендация исполнителя. Сначала детерминированный фильтр (компетенция по продукту, нужный уровень), затем ранжирование | Доля принятых рекомендаций ≥ 60 %; 0 рекомендаций инженера без нужной компетенции | Журнал решений; автотест фильтра |
| ИИ-04 | А4: черновик ответа | ≥ 50 % черновиков утверждены без существенных правок; 0 ссылок на несуществующие статьи базы знаний; 0 обещаний сроков выхода версий, которых нет в базе знаний | Журнал решений; автоматическая проверка ссылок; выборочная экспертиза |

### Объяснимость

| ID | Требование |
|---|---|
| ИИ-05 | Каждое предложение содержит: краткое обоснование на русском языке; использованные источники (ID статей базы знаний, ID похожих заявок); оценку уверенности 0–1. Для А3 — факторы рекомендации: загрузка, совпадение компетенций, число прошлых заявок клиента у этого инженера |

### Полномочия и безопасность

| ID | Требование |
|---|---|
| ИИ-06 | Агент работает только через инструменты из allow-list (раздел 4.1). Запись — только в поле «предложение ассистента». Любой другой вызов отклоняется на стороне MCP-сервера и журналируется |
| ИИ-07 | Текст заявки, переписка и вложения — **недоверенные данные**. Инструкции в них не исполняются (защита от prompt injection). Приёмка: набор ≥ 20 сценариев внедрения инструкций, 0 успешных попыток выйти за allow-list или раскрыть данные другой организации |

### Поведение при деградации

| ID | Требование |
|---|---|
| ИИ-08 | Переход на детерминированную логику: если модель недоступна, ответ дольше 60 с или уверенность ниже порога (предл. 0,6), предложение не показывается. Заявка обрабатывается по процессу кейса без ассистента (BR-13: свободный инженер / назначение руководителем). SLA-контур, уведомления и статусы от ИИ **не зависят**. У администратора есть выключатель ассистента целиком и по отдельным функциям А1–А4 |

### Данные

| ID | Требование |
|---|---|
| ИИ-09 | Для обучения и оценки используются исторические заявки с разметкой типа, итогового приоритета и исполнителя. Для учебного прототипа — синтетический набор ≥ 200 заявок, построенный по описанию кейса. Персональные данные (ФИО, контакты, адреса серверов) маскируются до передачи в модель (НФТ-09). Данные одной организации не попадают в контекст при обработке заявок другой |

### Мониторинг и журналирование

| ID | Требование |
|---|---|
| ИИ-10 | Еженедельно считаются: доля принятых предложений по А1–А4, accuracy А1 на выборочно размеченных заявках, распределение типов и продуктов (дрейф), задержка, стоимость обработки одной заявки. Если доля принятых предложений по функции падает ниже порога две недели подряд, функция автоматически отключается до разбора (переход по ИИ-08) |
| ИИ-11 | Журналируется каждый вызов инструмента (инструмент, аргументы, время, результат или его хеш), каждое предложение и решение человека (утвердил / изменил / отклонил, кто, когда) |
| ИИ-12 | Стоимость обработки одной заявки ассистентом укладывается в бюджет, который будет рассчитан на этапе 3 (ТЭО). До этого — фиксируется фактическая |
